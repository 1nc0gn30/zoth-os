1. What Happens When You Shut Off, Reboot, or Close the Machine?

            

              ZothOS-Lite boots using the Debian Live toram noswap slab_nomerge init_on_free=1 kernel parameters. At boot, the SquashFS operating system image loads completely into volatile system RAM.
            

            

              Zero Disk Forensics on Power-Off: Internal NVMe/SATA drives are never mounted automatically, and disk swap is strictly disabled (0 B). Once the desktop appears, you can even unplug your boot USB stick. When you power off or reboot, RAM loses electrical charge—permanently erasing temporary workspaces, shell history, browser cache, and RAM-only API keys.
            

            

              
# Launch the built-in onboarding check anytime inside the OS:
$ zoth-lite-welcome --check

# Verify amnesic kernel flags & zero swap:
$ cat /proc/cmdline     # -> boot=live components toram noswap ...
$ free -h               # -> Swap: 0B

# Instantly shred volatile API keys before powering off:
$ zoth-lite-models --wipe-keys

            

          


          
          

            
2. Connecting 56 Curated Models Across 8 Cloud & LAN Providers

            

              ZothOS-Lite runs fast on any lightweight laptop or thin client because inference routes either to DeepSeek Flash via Hermes Agent (Nous Research) and 7 other cloud gateways, or to a local/LAN Ollama server on your subnet. Keys set via zoth-lite-models live strictly in volatile RAM (/run/user/$UID/zoth-keys.env or /dev/shm, mode 0600)—never touching internal disks.
            

            

              
# List all 56 curated models across 8 providers (Ollama Local, Hermes / Nous,
# DeepSeek, OpenRouter, OpenAI, Anthropic, Google Gemini, and Groq):
$ zoth-lite-models --providers
$ zoth-lite-models --list

# Store an API key in volatile RAM (wiped on shutdown):
$ zoth-lite-models --set-key hermes
$ zoth-lite-models --set-key openrouter

# Point to an Ollama server on your local network (zero cloud needed):
$ zoth-lite-models --set-endpoint ollama http://192.168.1.50:11434/v1/chat/completions

# Test providers & run DeepSeek Flash via Hermes Agent directly from CLI:
$ zoth-lite-models --test
$ zoth-lite-models --run hermes:deepseek-flash "Generate a hardened Dockerfile"

            

          


          
          

            
3. Saving Agent Builds to External Hard Drives or Cloud Storage

            

              Because RAM clears on shutdown, anything you want to keep—codebases, agent outputs, or exported key vaults—should be synced to an external USB/SSD/NVMe drive or an encrypted cloud remote using zoth-lite-storage.
            

            

              
# 1. Inspect partitions safely (internal OS disks are marked SKIP):
$ zoth-lite-storage list

# 2. Mount an external USB/NVMe drive to /mnt/zoth-ext/sdb1:
$ sudo zoth-lite-storage mount /dev/sdb1

# 3. Sync your RAM workspace + generate a verified SHA-256 manifest:
$ zoth-lite-storage sync ./agent-build /mnt/zoth-ext/sdb1/builds

# 4. Or sync to Google Drive, AWS S3, Dropbox, or WebDAV via rclone:
$ rclone config
$ zoth-lite-storage sync ./agent-build s3remote:zoth-builds

            

          


          
          

            
4. Talking to Another Zoth User on ZothNet (Encrypted P2P)

            

              ZothOS-Lite includes the lightweight zothnet P2P mesh CLI so operators and AI agents can discover peers on the same Wi-Fi/LAN subnet or Tor/WireGuard mesh and exchange ChaCha20-Poly1305 encrypted messages with ephemeral RAM keys.
            

            

              
# 1. Check your ephemeral ZothNet node ID & port (:8102):
$ zothnet status

# 2. List active Zoth peers discovered on LAN or Onion mesh:
$ zothnet peers

# 3. Send an end-to-end encrypted message to another Zoth user:
$ zothnet chat @zoth-relay-lan01 "Build passed SHA-256 check, ready to pull"

            

          


          
          

            
5. Installing Extra Tools On-Demand Without Bloating the OS

            

              ZothOS-Lite keeps its base footprint minimal so it boots fast and stays responsive. Pull extra Zoth modules or standard Debian/Python/Node packages into RAM OverlayFS only when a task calls for them.
            

            

              
# View core locked security tools & optional on-demand modules:
$ zoth-lite-pkg list

# Mount an optional module into volatile RAM_TMPFS:
$ zoth-lite-pkg install promptmaster-security-lab
$ zoth-lite-pkg install bolt-diy-sandbox

# Install local .deb packages or portable .AppImage binaries into RAM OverlayFS:
$ sudo dpkg -i ./my-tool_amd64.deb || sudo apt -f install -y
$ chmod +x ./Cursor.AppImage && ./Cursor.AppImage --appimage-extract-and-run
