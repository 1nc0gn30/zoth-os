Sovereign User Hierarchy

ZothOS enforces a dual-operator security architecture designed for segregated execution, security auditing, and continuous workflow testing:

👑 Primary Operator: zoth

UID: 1000  |  Default Password: zoth

The default live session user. Pre-provisioned with full KDE Plasma 6.3 desktop configurations, gold theme assets, verified tool shortcuts, and passwordless sudo access.

🛡️ Secondary Operator: azoth

UID: 1001  |  Default Password: zoth

Secondary administrative user reserved for sandboxed agent executions, build isolation, and root-level testing without polluting the primary desktop profile.

Root Sudo Access: Both zoth and azoth have passwordless administrative privileges via /etc/sudoers.d/010_zoth-nopasswd. Legacy installer accounts (such as neo) have been completely removed from system manifests.

Dual Repositories & Pinning Architecture

ZothOS integrates three world-class package repositories unified under intelligent Debian APT pinning:

  • Debian Trixie (Debian 13) [Priority 900]: Core operating system, systemd, libc6, display server, and KDE Plasma 6 environment.
  • Kali Linux Rolling [Priority 500]: Full offensive security, wireless penetration, and exploitation tool catalog.
  • Parrot Security [Priority 500]: Privacy, digital forensics, reverse engineering, and cryptography tool suites.

This pinning strategy guarantees that running sudo apt install <tool> immediately installs any package from Kali or Parrot without risking core system library collisions or breaking Debian desktop stability.

Architecture & Multi-Tier Runtime

Zoth Studio Pro operates on a resilient multi-tier standalone architecture. When launched via zoth-studio, the system executes the following boot sequence:

  1. Local Asset Server Daemon: Spawns an internal HTTP server bound to 127.0.0.1 on the first available port (preferred: 3000, 8088, 8080) serving pre-rendered static assets.
  2. Multi-Tier Window Display:
    • Tier 1 (Preferred): Native Electron standalone application window with GPU sandbox fallbacks.
    • Tier 2 (Fallback): Native WebKit2GTK standalone window with hardware-accelerated WebGL.
    • Tier 3 (Browser Window): Dedicated standalone application window via Google Chrome, Chromium, or Firefox.
BASH # Launch Zoth Studio Pro from any terminal: zoth-studio # Launch directly in browser mode: zoth-studio --browser # Trigger instant Studio update / rebuild: zoth-studio --update

Operational Do's & Don'ts

Guidelines for maintaining OPSEC, system integrity, and key safety.

DO: Use zoth-vault run -- <cmd> to execute tools requiring API keys so secrets remain exclusively in process memory.
DO: Use zoth-mode ghost or zoth-ghost start before initiating audits on public networks.
DO: Use zoth-netkill instantly if unverified outbound sockets are detected.
DON'T: Write raw plain-text secret keys or tokens to .env files on unencrypted media.
DON'T: Run arbitrary pipe-to-bash (curl | bash) scripts without inspecting their cryptographic signatures.
DON'T: Disable the root partition overlay or write credentials to the live ISO filesystem.
